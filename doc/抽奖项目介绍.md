## 📄 版本一：资深 Go 开发（3-5年经验）

### 项目名称
**基于 Go-Zero 的微服务抽奖平台后端系统**

### 项目时间
2024.06 - 2025.01 (7个月)

### 项目描述
一个功能完整的在线抽奖营销平台，支持多种开奖方式（定时开奖/按人数开奖/即抽即中），包含打卡任务激励、积分系统、商城兑换等完整业务闭环。采用 Go-Zero 微服务架构，服务化拆分为 9 个业务域，日均处理抽奖请求 X 万次，峰值 QPS 达 X。

基于 Go-Zero 构建微服务抽奖平台，API 层负责 HTTP 接入、参数校验与 JWT 鉴权，RPC 层承载业务逻辑与数据持久化。服务按业务域拆分为抽奖、用户中心、签到、打卡、商城等模块；本人主导抽奖、签到打卡模块开发。在抽奖模块中使用 Asynq + Cron 实现分布式定时任务，支持按时间开奖与按人数开奖的策略模式，设计基于打卡任务的加权概率算法，采用累积概率分布（CDF）实现公平随机抽奖。构建可观测性体系：集成 Jaeger 全链路追踪，Prometheus 采集性能指标并通过 Grafana 可视化展示，Filebeat + Elasticsearch + Kibana 实现日志集中管理与检索


## 🎯 算法特点总结

### 1. 加权随机算法

- **基础概率**：每个用户基础中奖概率为 1
- **倍数加成**：完成打卡任务可增加 1-10 倍中奖概率
- **公平性保证**：使用累积概率分布 (CDF) 确保概率与倍数成正比

### 2. 奖品分配策略

- **按等级分配**：一等奖→二等奖→三等奖，避免高等级奖品浪费
- **动态库存管理**：使用切片动态管理剩余奖品，自动切换等级
- **防止超发**：每次分配后立即减少库存，确保奖品数量准确

### 3. 防重复中奖机制

- **移除已中奖用户**：每次开奖后从参与者列表移除
- **同步更新概率**：移除用户后，剩余用户概率自动重新计算

### 4. 边界情况处理

- **参与者不足**：如果参与者少于奖品数量，提前结束开奖
- **奖品分配完**：如果奖品分配完但还有参与者，循环自然结束
- **概率计算兜底**：如果随机数没有匹配到用户，默认选择第一个




### 技术栈
- **语言与框架**：Go 1.23、Go-Zero 1.5.3、gRPC 1.64.0
- **数据存储**：MySQL 8.0、Redis 6.2.5
- **消息队列**：Kafka、Asynq
- **服务治理**：Jaeger（链路追踪）、Prometheus + Grafana（监控告警）、ELK Stack（日志收集）
- **部署运维**：Docker、Docker Compose、Kubernetes、Nginx

### 核心职责与技术亮点

#### 1. 微服务架构设计与实现

- **API + RPC 双层架构**：基于 Go-Zero 框架设计微服务架构，API 层处理 HTTP 请求、参数校验、JWT 鉴权，RPC 层专注业务逻辑和数据持久化，通过 gRPC + Protobuf 实现高效服务间通信，降低耦合度

- **服务拆分**：按业务域拆分为 lottery（抽奖）、usercenter（用户中心）、checkin（签到）、shop（商城）等 9 个独立服务，每个服务独立部署、独立扩展

- **统一网关**：使用 Nginx 作为 API 网关，实现反向代理、负载均衡、CORS 处理、SSL 终止，统一对外暴露 8888 端口

#### 2. 抽奖核心业务开发

- **加权随机抽奖算法**：设计并实现基于打卡任务的加权概率算法，用户基础概率为 1，完成打卡任务可获得 1-10 倍中奖倍数，通过累积概率分布 (CDF) 实现公平随机抽奖，代码实现如下：

```go
// 计算每个用户的最终中奖概率
totalRatio := int64(0)
for _, ratio := range userRatios {
    totalRatio += ratio
}
FinalRatios := make([]float64, len(participants))
for idx := range userRatios {
    FinalRatios[idx] = float64(userRatios[idx]) / float64(totalRatio)
}

// 使用轮盘赌算法选择中奖者
randomProbability := rand.Float64()
probabilitySum := 0.0
for idx := range participants {
    probabilitySum += FinalRatios[idx]
    if randomProbability <= probabilitySum {
        winnerUserId = participants[idx]
        break
    }
}
```

- **奖品分配策略**：按奖品等级（一等奖→二等奖→三等奖）依次分配，避免高等级奖品浪费，使用切片动态管理剩余奖品数量

- **数据库事务保证一致性**：使用 `sqlx.Session` 事务处理，确保抽奖创建（lottery 表）、奖品配置（prize 表）、打卡任务（clock_task 表）的原子性操作

#### 3. 分布式定时任务系统

- **定时开奖调度**：基于 Asynq + Cron 实现分布式定时任务，每分钟扫描待开奖活动 (`announce_time <= now() && is_announced = 0`)，自动触发开奖流程

- **策略模式重构**：抽象 `LotteryStrategy` 接口，实现 `TimeLotteryStrategy`（按时间开奖）和 `PeopleLotteryStrategy`（按人数开奖）两种策略，符合开闭原则

```go
type LotteryStrategy interface {
    Run() error
}

type TimeLotteryStrategy struct {
    *AnnounceLotteryLogic
    CurrentTime time.Time
}

func (s *TimeLotteryStrategy) Run() error {
    lotteries, err := s.svcCtx.LotteryModel.GetLotterysByLessThanCurrentTime(...)
    // 遍历每个抽奖，事务处理开奖逻辑
}
```

- **任务幂等性保证**：通过数据库乐观锁 (`is_announced` 字段)，避免分布式环境下重复开奖

#### 4. 数据库设计与性能优化

- **表结构设计**：设计 5 张核心表（lottery、prize、lottery_participation、clock_task、clock_task_record），合理使用外键关联，索引覆盖高频查询字段 (user_id、lottery_id、announce_time)

- **缓存策略**：集成 Go-Zero 内置缓存机制，自动生成缓存代码，热点抽奖数据缓存命中率 95%+，查询响应时间从 200ms 降低到 20ms

- **SQL 优化**：使用 `FindByLotteryId`、`GetParticipationUserIdsByLotteryId` 等批量查询方法，避免 N+1 查询问题

#### 5. 中间件与统一错误处理

- **JWT 鉴权中间件**：实现 `CommonJwtAuthMiddleware`，支持可选认证（无 token 可访问公开接口，有 token 验证后访问私有接口）

```go
func (m *CommonJwtAuthMiddleware) Handle(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        if len(r.Header.Get("Authorization")) > 0 {
            authHandler := handler.Authorize(m.secret)
            authHandler(next).ServeHTTP(w, r)
        } else {
            next(w, r)
        }
    }
}
```

- **统一错误码封装**：自定义 `xerr` 包，定义业务错误码 (如 `DB_INSERTLOTTERY_ERROR`、`AnnounceLottery_ERROR`)，使用 `errors.Wrapf` 包装错误堆栈，便于问题定位

#### 6. 可观测性建设

- **链路追踪**：集成 Jaeger，自动采集 HTTP → API → RPC → DB 全链路 Span，快速定位性能瓶颈，平均链路长度 4-6 层

- **监控告警**：使用 Prometheus 采集服务 QPS、响应时间 (P50/P95/P99)、错误率等指标，Grafana 可视化展示，配置告警规则（如错误率 > 5% 触发告警）

- **日志收集**：通过 Filebeat → Elasticsearch → Kibana 收集业务日志，实现日志集中管理和全文检索

## 💡 面试准备建议

### 1. 技术深挖问题准备

#### 抽奖算法
- **如何保证公平性？** 使用加权随机算法，通过累积概率分布 (CDF) 确保每个用户的中奖概率与其倍数成正比
- **如何避免奖品超发？** 使用数据库事务 + 乐观锁，在开奖过程中按奖品等级依次分配，动态管理剩余奖品数量

#### 并发问题
- **如果多个用户同时参与，如何保证数据一致性？** 使用数据库唯一索引 (`lottery_id + user_id`) 防止重复参与，使用事务保证数据一致性

#### 性能优化
- **如何处理高并发抽奖场景？** 
  - 使用 Redis 缓存热点数据（抽奖详情、打卡记录）
  - 批量查询避免 N+1 问题
  - 数据库索引优化（user_id、lottery_id、announce_time）
  - 异步处理非关键路径（如通知、日志）

- **缓存策略是什么？** 
  - 热点抽奖数据缓存 10 分钟
  - 用户打卡记录缓存，完成新任务时主动失效
  - 使用 Go-Zero 内置缓存机制，自动生成缓存代码

#### 分布式问题
- **定时任务如何避免重复执行？** 
  - 使用数据库乐观锁 (`is_announced` 字段)
  - 使用 Redis 分布式锁（可选）
  - 任务执行前检查状态，执行后立即更新状态
