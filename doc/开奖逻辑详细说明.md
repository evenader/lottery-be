# 开奖逻辑详细说明：DrawLottery 函数

> 详细解析抽奖系统的核心开奖算法实现，包括加权随机算法、奖品分配策略等

---

## 📋 函数签名

```go
func (l *AnnounceLotteryLogic) DrawLottery(
    ctx context.Context, 
    lotteryId int64, 
    prizes []*model.Prize, 
    participantor []int64
) ([]Winner, error)
```

### 参数说明

- `ctx`: 上下文对象，用于链路追踪和超时控制
- `lotteryId`: 抽奖活动ID
- `prizes`: 奖品列表，包含奖品类型、数量等信息
- `participantor`: 参与者用户ID列表

### 返回值

- `[]Winner`: 中奖者列表，每个中奖者包含 `LotteryId`、`UserId`、`PrizeId`
- `error`: 错误信息

---

## 🔍 核心算法流程

### 整体流程图

```
开始
  ↓
1. 初始化随机数生成器
  ↓
2. 计算总中奖人数（所有奖品数量之和）
  ↓
3. 批量查询用户打卡记录（获取中奖倍数）
  ↓
4. 计算每个用户的中奖倍率（基础倍率 + 打卡任务倍数）
  ↓
5. 归一化计算每个用户的最终中奖概率
  ↓
6. 循环开奖（使用加权随机算法）
  ├─ 生成随机数
  ├─ 使用轮盘赌算法选择中奖者
  ├─ 按奖品等级分配奖品
  └─ 移除已中奖用户，继续下一轮
  ↓
7. 返回中奖者列表
```

## 📝 详细步骤解析

### Step 1: 初始化随机数生成器

```go
rand.New(rand.NewSource(time.Now().UnixNano()))
```

**作用**：使用当前时间戳作为随机数种子，确保每次开奖的随机性。

**注意**：这里存在一个小问题，`rand.New()` 返回的 `*rand.Rand` 对象没有被保存，后续使用的是全局的 `rand` 包函数。建议改为：

```go
r := rand.New(rand.NewSource(time.Now().UnixNano()))
// 后续使用 r.Float64() 而不是 rand.Float64()
```

---

### Step 2: 计算总中奖人数

```go
var WinnersNum int64
for _, p := range prizes {
    WinnersNum += p.Count
}
```

**作用**：遍历所有奖品，累加每个奖品的数量，得到总中奖人数。

**示例**：
- 一等奖：1个
- 二等奖：2个
- 三等奖：5个
- **总中奖人数 = 1 + 2 + 5 = 8人**

---

### Step 3: 批量查询用户打卡记录

```go
records, err := l.svcCtx.ClockTaskRecordModel.GetClockTaskRecordByLotteryIdAndUserIds(
    lotteryId, participantor)
```

**作用**：一次性批量查询所有参与者的打卡任务记录，获取每个用户完成的任务及其增加的中奖倍数。

**优化点**：使用批量查询避免 N+1 查询问题（详见 `性能优化案例-N+1查询问题.md`）。

**返回数据结构**：
```go
type ClockTaskRecord struct {
    UserId           int64  // 用户ID
    LotteryId        int64  // 抽奖ID
    IncreaseMultiple int64  // 增加的中奖倍数（1-10倍）
    // ... 其他字段
}
```

---

### Step 4: 计算每个用户的中奖倍率

```go
// 初始化：每个用户的基础倍率为1
RationsMap := make(map[int64]int64)
for _, participant := range participantor {
    RationsMap[participant] = 1
}

// 累加打卡任务增加的倍数
for _, record := range records {
    RationsMap[record.UserId] += record.IncreaseMultiple
}
```

**作用**：
1. 初始化每个用户的基础中奖倍率为 **1**
2. 遍历打卡记录，累加每个用户完成任务所增加的倍数

**示例**：
- 用户A：基础倍率1，完成2个任务（+3倍、+5倍）→ **总倍率 = 1 + 3 + 5 = 9**
- 用户B：基础倍率1，未完成任务 → **总倍率 = 1**
- 用户C：基础倍率1，完成1个任务（+2倍）→ **总倍率 = 1 + 2 = 3**

**倍率范围**：1 ~ 11（基础1 + 最多10倍）

---

### Step 5: 归一化计算最终中奖概率

```go
// 计算总倍率
totalRatio := int64(0)
for _, ratio := range Ratios {
    totalRatio += ratio
}

// 计算每个用户的最终中奖概率（归一化到0-1之间）
FinalRatios := make([]float64, len(participantor))
for idx := range Ratios {
    FinalRatios[idx] = float64(Ratios[idx]) / float64(totalRatio)
}
```

**作用**：将每个用户的倍率转换为概率，确保所有用户的概率之和为 1.0。

**数学公式**：
```
P(user_i) = Ratio(user_i) / Σ(Ratio(all_users))
```

**示例**：
假设有3个用户，倍率分别为 [9, 1, 3]：
- 总倍率 = 9 + 1 + 3 = 13
- 用户A概率 = 9/13 ≈ 0.692（69.2%）
- 用户B概率 = 1/13 ≈ 0.077（7.7%）
- 用户C概率 = 3/13 ≈ 0.231（23.1%）
- **验证**：0.692 + 0.077 + 0.231 = 1.0 ✅

---

### Step 6: 循环开奖（核心算法）

#### 6.1 外层循环：按中奖人数开奖

```go
for i := 0; i < int(WinnersNum); i++ {
    // 开奖逻辑
}
```

**作用**：循环 `WinnersNum` 次，每次产生一个中奖者。

#### 6.2 边界检查：参与者不足时提前结束

```go
if len(participantor) == 0 {
    break
}
```

**作用**：如果参与者数量少于奖品数量（例如：5个奖品但只有3个参与者），提前结束开奖，避免数组越界。

#### 6.3 生成随机数

```go
randomProbability := rand.Float64()  // 生成 [0.0, 1.0) 之间的随机数
```

**作用**：生成一个 0 到 1 之间的随机浮点数，用于轮盘赌算法。

#### 6.4 轮盘赌算法选择中奖者

```go
probabilitySum := 0.0
for idx := range participantor {
    probabilitySum += FinalRatios[idx]
    if randomProbability <= probabilitySum {
        winnerUserId = participantor[idx]
        randomWinnerIndex = idx
        break
    }
}
```

**作用**：使用**累积概率分布 (CDF)** 实现加权随机选择。

**算法原理**：
1. 将 [0, 1) 区间按用户概率划分
2. 用户A：[0, 0.692)
3. 用户B：[0.692, 0.769)
4. 用户C：[0.769, 1.0)
5. 随机数落在哪个区间，就选中对应的用户

**示例**：
- 随机数 = 0.5 → 落在 [0, 0.692) → **用户A中奖**
- 随机数 = 0.7 → 落在 [0.692, 0.769) → **用户B中奖**
- 随机数 = 0.9 → 落在 [0.769, 1.0) → **用户C中奖**

**可视化**：
```
[0.0 ──────────────── 0.692 ─── 0.769 ──────────── 1.0)
  │        用户A        │  用户B  │      用户C      │
  │      (69.2%)       │ (7.7%)  │    (23.1%)     │
```

#### 6.5 兜底逻辑：防止边界情况

```go
if winnerUserId == 0 {
    winnerUserId = participantor[0]
}
```

**作用**：如果由于浮点数精度问题导致没有选中用户（理论上不应该发生），默认选择第一个参与者。

---

### Step 7: 按奖品等级分配奖品

```go
// 按奖品类型排序（一等奖→二等奖→三等奖）
sort.Slice(prizes, func(i, j int) bool {
    return prizes[i].Type < prizes[j].Type
})

// 如果当前等级奖品已分配完，移除该等级
if prizes[0].Count == 0 {
    prizes = prizes[1:]
}

// 分配奖品并减少库存
prizes[0].Count--
prizeId := prizes[0].Id
```

**作用**：
1. **按等级排序**：确保先分配高等级奖品（一等奖→二等奖→三等奖）
2. **动态管理库存**：每次分配后减少奖品数量
3. **自动切换等级**：当前等级奖品分配完后，自动切换到下一等级

**示例**：
- 第1轮：分配一等奖（Type=1, Count=1）→ Count变为0 → 移除一等奖
- 第2轮：分配二等奖（Type=2, Count=2）→ Count变为1
- 第3轮：分配二等奖（Type=2, Count=1）→ Count变为0 → 移除二等奖
- 第4轮：分配三等奖（Type=3, Count=5）→ Count变为4
- ...

**优势**：
- ✅ 避免高等级奖品浪费（优先分配）
- ✅ 保证奖品分配的公平性（按顺序分配）
- ✅ 动态管理，无需预先分配

---

### Step 8: 移除已中奖用户

```go
// 从参与者列表中移除已中奖用户
participantor = append(participantor[:randomWinnerIndex], 
                      participantor[randomWinnerIndex+1:]...)
// 同步移除对应的概率
FinalRatios = append(FinalRatios[:randomWinnerIndex], 
                     FinalRatios[randomWinnerIndex+1:]...)
```

**作用**：
1. **防止重复中奖**：已中奖的用户不能再次中奖
2. **重新归一化概率**：移除用户后，剩余用户的概率会自动重新归一化（因为使用的是相对概率）

**示例**：
- 初始：用户A(69.2%), 用户B(7.7%), 用户C(23.1%)
- 第1轮：用户A中奖，移除用户A
- 剩余：用户B(7.7%), 用户C(23.1%)
- 重新计算：用户B = 1/(1+3) = 25%, 用户C = 3/(1+3) = 75%

**注意**：移除用户后，`FinalRatios` 数组需要同步更新，否则索引会错乱。

## 🎯 算法特点总结

### 1. 加权随机算法

- **基础概率**：每个用户基础中奖概率为 1
- **倍数加成**：完成打卡任务可增加 1-10 倍中奖概率
- **公平性保证**：使用累积概率分布 (CDF) 确保概率与倍数成正比

### 2. 奖品分配策略

- **按等级分配**：一等奖→二等奖→三等奖，避免高等级奖品浪费
- **动态库存管理**：使用切片动态管理剩余奖品，自动切换等级
- **防止超发**：每次分配后立即减少库存，确保奖品数量准确

### 3. 防重复中奖机制

- **移除已中奖用户**：每次开奖后从参与者列表移除
- **同步更新概率**：移除用户后，剩余用户概率自动重新计算

### 4. 边界情况处理

- **参与者不足**：如果参与者少于奖品数量，提前结束开奖
- **奖品分配完**：如果奖品分配完但还有参与者，循环自然结束
- **概率计算兜底**：如果随机数没有匹配到用户，默认选择第一个

## 🔧 潜在问题与优化建议

### 问题1: 随机数生成器未保存

**当前代码**：
```go
rand.New(rand.NewSource(time.Now().UnixNano()))
// 后续使用 rand.Float64() 使用的是全局随机数生成器
```

**建议优化**：
```go
r := rand.New(rand.NewSource(time.Now().UnixNano()))
// 后续使用 r.Float64()
```

### 问题2: 移除用户时索引可能越界

**当前代码**：
```go
participantor = append(participantor[:randomWinnerIndex], 
                      participantor[randomWinnerIndex+1:]...)
```

**潜在问题**：如果 `randomWinnerIndex` 等于数组长度，会导致越界。

**建议优化**：
```go
if randomWinnerIndex >= 0 && randomWinnerIndex < len(participantor) {
    participantor = append(participantor[:randomWinnerIndex], 
                          participantor[randomWinnerIndex+1:]...)
    FinalRatios = append(FinalRatios[:randomWinnerIndex], 
                        FinalRatios[randomWinnerIndex+1:]...)
}
```

### 问题3: 奖品排序可能重复执行

**当前代码**：每次循环都执行 `sort.Slice(prizes, ...)`

**优化建议**：在循环外排序一次即可，因为奖品是按等级顺序分配的。

```go
// 在循环外排序一次
sort.Slice(prizes, func(i, j int) bool {
    return prizes[i].Type < prizes[j].Type
})

for i := 0; i < int(WinnersNum); i++ {
    // 移除排序逻辑
}
```

### 问题4: 概率重新归一化

**当前实现**：移除用户后，`FinalRatios` 数组没有重新归一化，但由于使用的是累积概率，算法仍然正确。

**说明**：虽然 `FinalRatios` 数组的值没有更新，但算法通过累加的方式实现了隐式的重新归一化，这是正确的。

## 📊 算法复杂度分析

| 操作 | 时间复杂度 | 说明 |
|------|-----------|------|
| 计算总中奖人数 | O(M) | M = 奖品数量 |
| 批量查询打卡记录 | O(1) | 一次数据库查询 |
| 计算用户倍率 | O(N) | N = 参与者数量 |
| 归一化概率 | O(N) | N = 参与者数量 |
| 循环开奖 | O(W × N) | W = 中奖人数，N = 参与者数量 |
| 奖品排序 | O(M log M) | M = 奖品数量 |

**总体复杂度**：O(M log M + W × N)

**实际场景**：
- 奖品数量 M ≈ 3-5（通常只有3个等级）
- 中奖人数 W ≈ 10-100
- 参与者数量 N ≈ 100-10000

**优化建议**：如果参与者数量很大（>1000），可以考虑使用更高效的随机选择算法，如别名采样（Alias Sampling），时间复杂度可降至 O(W)。

## 🎓 面试常见问题

### Q1: 如何保证抽奖的公平性？

**答案**：
1. **加权随机算法**：使用累积概率分布 (CDF) 确保每个用户的中奖概率与其倍数成正比
2. **随机数生成**：使用时间戳作为种子，确保每次开奖的随机性
3. **防重复中奖**：已中奖用户从参与者列表移除，确保每个用户最多中奖一次

### Q2: 如何避免奖品超发？

**答案**：
1. **动态库存管理**：每次分配后立即减少奖品数量 (`prizes[0].Count--`)
2. **按等级分配**：优先分配高等级奖品，避免浪费
3. **边界检查**：如果奖品分配完或参与者不足，提前结束循环

### Q3: 如果多个用户同时参与，如何保证数据一致性？

**答案**：
1. **数据库事务**：开奖过程在数据库事务中执行，保证原子性
2. **乐观锁**：使用 `is_announced` 字段防止重复开奖
3. **唯一索引**：参与记录表使用 `(lottery_id, user_id)` 唯一索引防止重复参与

### Q4: 加权随机算法的实现原理？

**答案**：
1. **计算倍率**：基础倍率1 + 打卡任务增加的倍数
2. **归一化概率**：将倍率转换为概率，确保总和为1.0
3. **轮盘赌算法**：生成随机数，使用累积概率分布选择中奖者
